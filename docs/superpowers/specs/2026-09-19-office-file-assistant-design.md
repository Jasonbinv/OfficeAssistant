# 办公文件助手（第一期）设计

日期：2026-09-19  
状态：待用户审阅（2026-09-19 第二次复核已写入裁决）  
产品：Windows 桌面应用，本机处理文件，不上传

## 1. 目标

给办公人员（先自己用，按能发给同事的标准做）一个中文桌面工具，第一期只做三件事：

1. 将多个 PDF **整份按顺序合并**成一份新文件
2. 从单个 PDF **删除页面**（页码 + 缩略图）
3. **重命名**目录中的文件：主用法是粘贴「一行一个新名字」的名单并对照预览；次用法是规则模板

默认不破坏原文件；重命名默认改原文件名（图纸整理的实际需求）。

## 2. 范围

### 2.1 第一期包含

- 单窗口、左侧功能导航：合并 PDF / 删除页面 / 重命名
- 资源管理器拖入文件或文件夹（见各功能规则）
- 后台执行、可取消、中文对错说明
- 加密 PDF：按文件弹出密码框
- 绿色免安装包（PyInstaller 目录版，双击可运行）
- 重命名完成后可「撤销上次重命名」

### 2.2 第一期不包含

- 按 PDF 正文/OCR 自动取名
- Office 转 PDF、图片转 PDF
- 跨文件挑页合并、从多份 PDF 各选页再合成
- 旋转、提取页面、拆分、压缩
- 云同步、账号、自动更新
- 递归处理子文件夹
- 安装程序、多语言界面

## 3. 技术选型

| 层 | 选择 | 原因 |
| --- | --- | --- |
| 语言 / UI | Python 3.12+、PySide6 | Windows 桌面、列表拖动和表格好做；LGPL 便于分发 |
| PDF 读写 | pypdf | 合并、删页；BSD 许可 |
| 缩略图 | pypdfium2 | 基于 PDFium，许可宽松，够用 |
| 打包 | PyInstaller onedir | 启动比 onefile 快，发给同事解压即用 |

不使用 PyMuPDF：AGPL 不适合把 exe 发给同事却不保证开源。

## 4. 架构

三层，互不直接操作对方的内部细节：

```
界面层（PySide6）
  → 组装「任务」：输入路径、选项、输出策略
任务层（QThread / Worker）
  → 预检 → 执行 → 进度/取消 → 汇总结果
文件层
  → pdf_ops：合并、删页、渲染缩略图（不独占锁文件）
  → naming.py：净化、模板、自然排序、页码范围解析（无 Qt、无磁盘）
  → rename_ops：名单配对、预检、改名、撤销
  → fs_ops：占用检测、另存冲突、写入不完整文件时的清理
```

固定模块：

- **输出策略**：合并只另存；删页默认另存、可选覆盖原文件；重命名默认原地改名、可选复制为新文件并保留原件
- **后台任务**：UI 线程不跑 PDF/磁盘重活；取消令牌可中断
- **缩略图缓存**：按可见区域渲染，低分辨率；打开文件用共享读，避免自己锁死导致无法覆盖
- **命名与校验**：模板变量、非法字符、重名、占用、加密

失败时：已写出的不完整**新文件**要删掉；**原文件**保持执行前状态（重命名已成功的条目除外，见 7.3）。

## 5. 界面

### 5.1 整体

- 应用名：**办公文件助手**
- 左侧导航三个入口，右侧为当前功能工作区
- 底部或工作区末行：进度条、取消、最近一次结果摘要

### 5.2 合并 PDF

- 工具：添加文件、移除、上移/下移、清空
- 可拖动排序的文件列表；同一路径不能添加两次
- 拖入：加入 PDF 文件；拖入文件夹则加入该层（不递归）中的 PDF。损坏与加密文件也进列表并标红，方便看见漏了哪份
- 加入时用无密码尝试打开：能打开为完好；需要密码则标红「需要密码」，用户可点该行输入；密码错误保持失败，不自动空密码重试。打不开的标红「损坏」
- 非 PDF、损坏、未解密：默认**不能开始合并**。用户可移除它们，或明确选择「合并其余完好文件」（仍须至少 2 个完好 PDF，否则按钮保持禁用）
- 无「覆盖原文件」。主按钮：开始合并 → 另存对话框。默认目录与文件名取**实际将合并的第一个完好文件**（不是列表里被跳过的坏文件）。输出路径不得与任一源文件相同（含将被跳过的源），否则提示换名
- 取消合并：删除不完整输出；不改任何源文件

### 5.3 删除页面

- 打开一个 PDF；可拖入 PDF。若一次拖入多个，只打开第一个并提示其余已忽略
- 页码输入：`1,3,5-8`，**从 1 起算**（与 Acrobat 一致）。按集合处理：去重、忽略空段。超出页数或无法解析的片段即时标红，不勾选无效页
- 页码框与缩略图双向同步。写回页码框时规范化：升序、连续页收成区间（如 `1,3,5,6,7,8` → `1,3,5-8`）
- 缩略图网格：勾选的是**要删除**的页；最长边约 160px；只渲染可见区域。切换文件时取消上一份的渲染任务
- 全选 / 反选针对当前文档全部页
- 全选 / 反选
- 未选任何页：执行按钮禁用
- 若删除后剩余 0 页：禁止执行
- 主按钮：另存为；勾选「覆盖原文件」时不走另存对话框，二次确认后覆盖
- 若另存选中的路径与源文件相同，视为覆盖原文件，走同一套二次确认，不另写一份再删原件
- 保留各页原有尺寸与旋转，不统一纸张大小

### 5.4 重命名（主模式：名单）

布局：**上方粘贴框 + 下方一张对照表**（Excel 式）。

1. 选择目录（按钮或拖入文件夹）。提供「刷新」：重建文件快照，尽量按路径保留勾选；已粘贴的名单不清空。不自动监视目录变化
2. 拖入文件：必须同属一个目录，否则提示只支持同一文件夹。随后切换到该目录、自动勾选这些文件对应的扩展名类型，并只勾选拖入的那些文件
3. 扩展名筛选：默认仅 `pdf`；可勾选 `dwg`、`dxf`、`jpg`、`jpeg`、`png`、`tif`、`tiff`、`doc`、`docx`、`xls`、`xlsx`。不递归子目录。跳过隐藏文件、`desktop.ini`、`thumbs.db`
4. 对照表列：拖动手柄、是否参与、当前文件名、新文件名（净化后的最终名，含扩展名）
5. 默认按 Windows 资源管理器逻辑排序（`1、2、10` 而非 `1、10、2`）；用户可拖动改序
6. 多行文本框粘贴名单：去掉 UTF-8 BOM；按行分割；空白行（含只含空格）忽略；去掉每行首尾空白。从 Excel 复制带制表符时只取第一列，不按空格分列（图纸名里可以有空格）
7. 第 N 个**勾选中**的文件对应第 N 条有效名单行；未勾选的文件不消耗名单行
8. 文件多于名单：该文件新名列显示「（名单缺一行）」并标红。名单多于文件：对照表下方列出未使用的名单行并标红
9. 确认后只处理绿色配对行；没有任何绿色行时确认按钮禁用
10. 主按钮：确认重命名。可选项：复制为新文件、保留原文件（默认关闭）
11. 成功后可点「撤销上次重命名」

### 5.5 重命名（次模式：规则）

同一页用切换：「名单改名 | 规则改名」。规则模式不用粘贴框，按对照表当前顺序对**已勾选**文件应用模板。默认模板 `{原名}_{序号}`。

- `{原名}`：不含扩展名的当前名
- `{日期}`：当天本地日期 `YYYYMMDD`
- `{序号}`：从 1 起，按勾选顺序。位数 = max(2, 勾选数量的十进制位数)，例如 8 个 → `01`…`08`，100 个 → `001`
- 可填前缀、后缀（加在模板结果外，仍在扩展名之前）。模板、前缀、后缀全空则新主名为空，该行标红

规则模式同样走对照表预览和同一套预检。

## 6. 输出与命名规则

### 6.1 默认路径与文件名

| 操作 | 默认目录 | 默认文件名 |
| --- | --- | --- |
| 合并 | 实际将合并的第一个完好文件所在目录 | `{该文件主名}_合并.pdf` |
| 删页另存 | 源文件所在目录 | `{源主名}_删页.pdf` |
| 重命名原地 | 原目录 | 名单或模板给出的新主名 + **原扩展名** |
| 重命名复制 | 原目录 | 同上，原文件不动 |

用户可在另存对话框中改位置和名字。

### 6.2 另存目标已存在

询问三选一：**自动加序号**（`_2`、`_3`）/ **覆盖该目标** / **取消**。  
这与「覆盖原文件」不是同一件事。覆盖原文件必须再确认一次。

### 6.3 名单 → 新文件名

- 名单行一般不含扩展名；新文件名 = 净化(行文本) + 原扩展名（扩展名大小写与原文件一致，如 `.pdf` / `.PDF`）
- 若行文本已以相同扩展名结尾（大小写不敏感），不再追加。若行文本以**其它**扩展名结尾（如源是 `.pdf`、行是 `foo.dwg`），仍再追加原扩展名，得到 `foo.dwg.pdf`，并在预览中原样展示，由用户自己改名单
- 净化顺序：先按 5.4 规则取出单元格文本 → 删除控制字符和 `\ / : * ? " < > |` → 去掉首尾空白 → 去掉末尾的点和空格（Windows 不允许）
- 仅大小写变化（`A.pdf` → `a.pdf`）在 NTFS 上视为需要改名，必须走临时名，不能直接 `rename`
- 净化后主名为空：该行标红，不执行
- Windows 保留设备名（`CON`、`PRN`、`AUX`、`NUL`、`COM1`–`COM9`、`LPT1`–`LPT9`）视为非法，该行标红
- 最终完整路径过长导致系统拒绝写入：该行标红（预检用与执行相同的路径拼接结果）

## 7. 预检、执行与错误

共同原则：对照表/列表上的状态就是将要发生的事；点确认前把能预见到的错误标出。执行中新出现的失败只应是占用、消失、磁盘满。

### 7.1 合并

预检：将参与合并的完好 PDF ≥ 2；输出路径有效且不等于任一源路径。损坏、非 PDF、加密未解密：标红。选择「合并其余完好文件」时，完好数量仍须 ≥ 2。  
执行：按列表中完好文件的顺序追加页面。取消：删除不完整输出文件。  
已知限制：数字签名会失效；书签/大纲尽量保留，不保证跨文件书签完美。不作为缺陷。

### 7.2 删页

预检：文件可读、密码已提供、删除集非空且至少留 1 页。  
覆盖原文件：先确认；若源文件被其他程序占用则停止并提示关闭后重试；本程序缩略图不得以独占方式锁文件。  
取消：若是另存，删除不完整新文件；若尚未替换原文件，原文件不变。覆盖过程采用「写临时文件再替换」，替换前失败则原文件仍在。

### 7.3 重命名

**点确认前必须预检（写进对照表）：**

- 非法/空名、本次绿色行之间目标名重复
- **原地改名：** 目标已被「本批不会改走」的文件占用则标红。本批会改走的旧名可以腾给别人（允许 A→B、B→C 以及互换）。仅大小写变化视为需要改名
- **复制模式：** 不腾出旧名。目标已存在（含另一行也要复制到同一名字）则标红，不做链式腾挪
- 新旧文件名相同（含扩展名、大小写都相同）：标为「无需改名」，不算绿色可执行行，也不进入撤销清单
- 没有绿色可执行行：确认按钮禁用

**执行前再预检一次。** 若绿色集合相对确认时有变化（文件消失、新的碰撞、目录内容变了）：**整批不执行**，刷新对照表，提示「文件已变化，请确认后重试」。这不属于「执行中单行失败」。

**执行：**

- 只处理绿色行
- 一对一、互不影响的行：执行中才出现的占用/消失 → 跳过该行，继续其余行
- 互换或链式依赖的一组：必须整组预检通过才开始；组内用临时名两阶段。组内执行失败 → 尽量把该组已改动的改回；改不回则在汇总中列出残留临时名（前缀 `.~$oa$`），不继续该组其余文件。其它独立行仍可继续
- 复制模式：复制失败不删原件；取消时删除已写出的不完整副本

**取消：** 已成功的不自动回滚；未处理的停止。取消后若已有成功项，仍记为「最近一批」，可撤销。  
**撤销：** 只记最近一批（含取消导致的部分成功）。再执行新一批后覆盖记忆。原地撤销 = 改回旧名（仍走预检与临时名）。复制撤销 = 删除复制出的新文件，不删原件。撤销时若旧名位置已有别的文件，该条失败并说明。

半批改名不可作为「预检或执行前再预检就能发现、却拖到改了一半才报」的结果。

### 7.4 提示语言

全部用户可见字符串为简体中文。汇总示例：「成功 8 个，跳过 1 个（未配对），失败 1 个（文件被占用：xxx.pdf）」。

## 8. 数据流（摘要）

1. 用户选路径 / 拖入 → 界面层列出快照（不监视目录自动刷新；提供「刷新」）
2. 用户改选项、名单、顺序 → 任务层纯函数计算预览行（无磁盘写）
3. 用户确认 → Worker：再跑一遍预检（失败则整批不写盘）→ 执行 → 信号回界面
4. 界面展示汇总；本批至少成功 1 个重命名/复制则启用撤销

## 9. 测试

自动化（pytest，临时目录 + 小型夹具 PDF）：

- 名单配对：多行、少行、空白行、Excel 制表符只取第一列、重复新名、已带相同扩展名不再重复后缀、带其它扩展名则再追加原扩展名
- 文件名净化：非法字符、末尾空格和点、空主名、保留设备名、仅大小写变化
- 自然排序：`1、2、10`
- 页码：解析与规范化写回（`1,3,5,6,7,8` → `1,3,5-8`）、越界、去重；禁止剩余 0 页
- 预检：目标已存在（原地可腾挪 vs 复制不可腾挪）、无需改名、没有绿色行不可执行
- 链式改名 / 互换 / 仅大小写改名成功；复制模式碰到已存在目标失败且原件仍在
- 合并：≥2 文件页序正确；坏文件拦住；输出路径等于源路径拒绝；取消后无残缺输出
- 加密：无密码失败且原文件不变
- `unique_path`：目标已存在时生成 `name_2.ext`、`name_3.ext`
- 执行前再预检失败则零写入
- 撤销上次重命名（原地与复制两种）；取消后的部分成功也可撤销

不强制 GUI 自动化。发布前手工走通：合并、删页（页码+缩略图）、名单改名（含数量不一致）、规则改名、覆盖确认、拖入文件。

## 10. 打包与分发

- PyInstaller onedir，内含 Python 与依赖
- 入口文件名：`OfficeAssistant.exe`；窗口标题与关于信息：**办公文件助手**
- 说明用简短 `使用说明.txt`：解压、双击、文件只在本机
- 随包附 Qt / PySide6 的 LGPL 许可文本（动态链接 Qt 库）
- `.superpowers/` 仅设计阶段线框，不进入发布包，应列入 `.gitignore`

## 11. 建议的代码布局

```
src/office_assistant/
  app.py                 # 入口
  ui/                    # 主窗、三页、对照表
  tasks/                 # Worker、进度、取消
  pdf_ops.py
  rename_ops.py
  fs_ops.py
  naming.py              # 净化、模板、自然排序、页码范围解析
tests/
docs/superpowers/specs/
```

界面只依赖任务层公开 API；`naming.py` / `rename_ops.py` 无 Qt 依赖，便于测试。

## 12. 成功标准

同事解压后能在无 Python 环境的 Windows 10/11 上：把若干 PDF 合成一份、删掉指定页、把扫描件按图纸目录名单一次改名，且预览与最终文件名一致；出错时原件仍在（除用户确认过的覆盖/原地改名外）。
